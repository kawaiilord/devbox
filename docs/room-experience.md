# 公开房间、访客与共享片单

## 使用流程

登录用户可在大厅「发现房间」中按关键词、分类、标签查找公开房间。
未登录用户也可浏览；开启访客访问的房间可输入昵称加入。知道房间码的访客可从登录页直接加入。
房间默认私密、禁用访客。房主在「房间设置」中设置公开状态、简介、分类、标签、密码和自动连播。
设置新密码时留空保留原值，移除密码需要明确勾选。

房间顶部的「片单 / 画质 / 来源」支持：

- 添加直链，或从已连接平台/NAS/媒体库批量选片；
- 拖动排序、移除剧集、上一集/下一集，以及房主在线时自动连播；
- 每集最多 8 个来源，切换备用来源或平台提供的画质；
- 同一集换源/换画质保持播放位置，切集从头播放；清空片单会停止播放。

删除正在播放的剧集会切换到邻近剧集。自动连播由房主客户端发起，服务端校验当前剧集与版本，
防止重复跳集。直播不使用点播式时间拖动与倍速。

## 权限

| 身份 | 默认权限 |
|---|---|
| 房主 | 播放、片单、聊天、弹幕、语音，并可管理房间与成员 |
| 协管员 | 播放、片单、聊天、弹幕、语音；不能修改房主或成员授权 |
| 成员 | 聊天、弹幕、语音，跟随播放 |
| 访客 | 只观看，仅可使用所在房间的接口 |

房主可逐人覆盖播放、片单、聊天、弹幕、语音五项权限。授权在服务端校验，客户端同时隐藏或禁用对应操作。
移出成员会禁止其重新加入并断开连接；关闭访客访问会移除现有访客。普通成员和访客主动离开会释放成员名额。
房主离开不删除房间。

访客使用绑定房间、设备和到期时间的短时 JWT，最长 6 小时，不发放刷新令牌，不保存到客户端的长期会话存储。
访客不能借此访问其他房间、媒体源管理、后台或账号设置。公开房间列表不包含视频地址、凭据或密码哈希。

## 一致性与持久化

`room_features` 保存私有房间设置、密码哈希、片单和授权；返回给客户端时使用独立公开投影。
密码用 Argon2id 哈希。迁移会为旧房间保留当前影片作为初始片单。

房间变更使用 Redis 分布式租约（无 Redis 的本地模式使用互斥锁）和元数据版本检查。
数据库事务同时保存片单选择与媒体状态，Redis 原子更新媒体指向和播放状态；读取缓存时取得一致快照。
切集/换源递增 `source_version`；客户端丢弃旧版本指令与异步结果，重新获取新影片播放票据。

媒体票据绑定观看者、房间与播放版本，播放和字幕请求重新检查成员资格。
房间成员可播放获分享的片源，但不能浏览其他人的完整媒体库，也不会收到其登录凭据。
片源故障时仍保留房间界面，房主可刷新或更换来源。

## 主要接口

- `GET /api/v1/public/rooms?q=&category=&tag=&offset=&limit=`
- `POST /api/v1/rooms/{code}/guest`，`POST /api/v1/rooms/{code}/leave`
- `PUT /api/v1/rooms/{code}/settings`
- `PUT/DELETE /api/v1/rooms/{code}/members/{userID}`
- `GET/POST/PUT /api/v1/rooms/{code}/playlist`
- `DELETE /api/v1/rooms/{code}/playlist/{itemID}`
- `POST /api/v1/rooms/{code}/playlist/{itemID}/sources`
- `POST /api/v1/rooms/{code}/playback/select`
- `GET /api/v1/rooms/{code}/variants`

写入片单、设置和授权时携带 `expected_version`，冲突返回 409 并要求刷新。
权限恢复也可使用成员接口的 `unban: true`。本功能使用 SameFrame 的 JSON 协议。
