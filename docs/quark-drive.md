# 夸克网盘与房间共看

## 使用流程

1. 在大厅选择「从网盘或媒体库选片」或「我的媒体源」，点击「添加夸克」。
2. 点击「打开夸克网页登录」，在夸克官网完成登录。
3. 在电脑浏览器按 F12，打开「网络」，刷新文件列表，选择 `file/sort`
   请求，复制请求标头里的完整 Cookie 值，在应用的连接窗口粘贴。
4. 点击「验证并连接」，进入网盘文件夹，选择电影。
5. 大厅显示已选影片后，点击「创建并播放」，把房间码发给好友。
6. 好友登录同帧并输入房间码即可加入。播放、暂停和拖动仍由房主控制并同步。

夸克登录凭据只在连接窗口输入，不要粘贴到聊天、工单或房间消息中。
好友无需提供夸克账号，也不会收到房主的 Cookie。
登录失效后，打开媒体源菜单中的「更新夸克登录」，使用同一夸克账号重新
获取 Cookie。更新会保留媒体源 ID、收藏和房间引用。

## 已实现的接口

- `POST /api/v1/sources/quark`：提交 `{name, cookie}`；验证目录读取成功后保存。
- `PUT /api/v1/sources/{id}/quark-cookie`：更新本人夸克源的登录凭据。
- `GET /api/v1/sources/{id}/files?path=/`：分页读取并汇总目录，仅展示文件夹和视频。
- 既有建房接口提交 `media_source_id`、`media_path`，进房和票据续期继续使用现有接口。

路径由不透明文件 ID 组成。目录每页读取 100 条，最多汇总 5,000 条，超出时返回
明确提示，不把截断的列表伪装成完整目录。

## 凭据与播放

- Cookie 用 AES-256-GCM 加密，并绑定用户和媒体源 ID；客户端不持久化它。
- 夸克响应中的登录 Cookie 轮换也会加密保存；比较旧密文后更新，防止并发请求
  覆盖新登录或恢复已删除的源。
- 夸克 API 地址固定，拒绝 API 重定向；不接受客户端传入的第三方 API 地址。
- 房间与 Redis 票据只引用媒体源和文件 ID，不保存夸克 Cookie 或上游签名 URL。
- 每次 GET/HEAD/Range 请求都重新获取下载地址。上游返回 401/403 时只额外刷新一次。
- 视频经同帧服务器流式转发，支持 Range/If-Range；仅向 `quark.cn` 及其子域发送
  夸克 Cookie，第三方签名 CDN 地址不会收到 Cookie。所有媒体跳转必须使用 HTTPS，
  并在连接时拒绝内网/保留地址，即使开启了私有 WebDAV 开发选项也不放宽。
- 房间成员获取短时票据，只有媒体源拥有者可以浏览完整目录、更新或删除登录。

部署需配置稳定的 `SAMEFRAME_VAULT_KEY`、Redis 和可访问夸克的服务器网络。
公网部署使用 HTTPS，播放器的网络流量会经过同帧服务器。

## 验证范围与边界

当前为**网页登录后导入 Cookie**，没有内嵌二维码登录或夸克账号密码登录。
播放的是原始文件流，实际可播放格式取决于客户端解码能力；Web 端不保证所有
MKV/音轨编码可播。本次不包含夸克转码/HLS、分享链接解析、外部字幕发现。
网盘账号权限、限速和服务端带宽仍影响播放速度。

自动化测试使用可控的夸克响应，覆盖登录验证、分页、凭据轮换、重新登录、
加密存储、跨用户访问隔离、Range/HEAD、签名地址重新获取、重定向凭据隔离、
好友加入房间和短时票据播放；PostgreSQL/Redis 在 CI 中验证。
这些测试不代替真实夸克账号的验收。尚未使用用户真实网盘完成端到端实播。

接口依据来自项目组维护的
[OpenList 夸克驱动协议实现](https://github.com/OpenListTeam/OpenList/tree/main/drivers/quark_uc)
及本次提供蓝图中的 Cookie 接入方式；不是夸克官方 OAuth/SDK 集成。
第三方网页接口变化可能需要适配。
