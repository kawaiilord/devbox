# Reviews and object storage

SameFrame stores review text, ratings, comments, and private object keys in
PostgreSQL. Image bytes are stored in an S3-compatible private bucket. Clients
request a ten-minute presigned PUT URL, upload directly to the bucket, and then
submit only the resulting object key with the review. Review reads return
15-minute presigned GET URLs; bucket credentials and permanent public URLs are
never sent to clients.

## Configuration

Set all four variables to enable image uploads:

```text
SAMEFRAME_S3_ENDPOINT=minio.example.com:9000
SAMEFRAME_S3_ACCESS_KEY=...
SAMEFRAME_S3_SECRET_KEY=...
SAMEFRAME_S3_BUCKET=sameframe-private
```

The endpoint must be an `https://` URL (or `http://` for a trusted local MinIO
deployment) containing only a hostname and optional port, without credentials,
path, query, or fragment. The bucket must already
exist and remain private. If configuration is absent, text-only reviews and
comments continue to work, while the upload-signing endpoint returns 503.

Browser deployments must configure bucket CORS for PUT and GET from the exact
SameFrame web origins. Permit `Content-Type`, avoid wildcard origins in
production, and do not grant LIST or DELETE to browsers.

## Limits and lifecycle

- JPEG, PNG, and WebP only; 10 MiB per image; at most four images per review.
- Keys are generated by the server under `reviews/<user-id>/`; client-provided
  arbitrary keys are rejected.
- The server verifies object existence, size, media type, and ownership before
  persisting a review.
- Replaced and deleted review images are removed on a best-effort basis.
- Configure a bucket lifecycle rule to expire unreferenced upload attempts.
  A conservative 24-hour cleanup for incomplete/staging objects is recommended.

The implementation uses MinIO's S3-compatible Go client and its presigned PUT
and GET APIs: <https://github.com/minio/minio-go/blob/master/docs/API.md>.
